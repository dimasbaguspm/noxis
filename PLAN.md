# noxis — plan v1

Personal multi-machine infra control plane. Go, single binary, role from CLI flag.

## Locked decisions (don't revisit without a reason)

1. **Transport:** master exposes a REST API (frontend/CLI); events flow over Kafka (apache/kafka + franz-go). Master publishes desired-state to per-node topics; slaves consume via durable groups (restart resumes from last offset — no reconnect/replay loops). Queries are request/reply over per-node topics keyed by request id. Topics named by NOXIS_TOPIC_PREFIX (independent environments share one broker), auto-created on demand (EnsureTopic). Broker is interchangeable via NOXIS_BROKER.
2. **Topology:** 1 master (durable desired-state + CLI) → N slaves (local reconcilers over Docker).
3. **Consensus:** none. Manual `--promote` failover. Raft only if auto-failover becomes real need.
4. **Storage on master:** SQLite. No database to manage your database manager.
5. **Engines:** containers, pinned images, one machine may run many (Docker separation). Engine = one small interface, `sqlEngine` base covers pg/mysql/maria, `mongoEngine` separate.
6. **Backup before any version bump. Manual apply per node. Auto-apply deferred.**
7. Replication payload = desired-state spec, never DB data. Managed DBs stay local to their node.

## Shape

```
cmd/noxis/
  main.go            thin entry
  bootstrap.go       env -> config -> logging -> root CLI (run/register)
  master/            server.go + routes.go + controller.go + middleware.go
  slave/             daemon.go (worker loop) + register.go + identity.go
internal/control/        master ops: registry repo + Kafka produce/consume/query
internal/repositories/   grouped by service:
  sqlite/                slave registry only (id, name, ip, registered_at)
  kafka/                 franz-go transport + EnsureTopic + Topics (env prefix)
  master/                typed methods for the master REST API
  slave/                 identity file (id, broker, topic prefix)
  docker/                docker CLI wrapper: exact argv for networks (+ NodeNetworkName/Label
                        conventions + NetworkReconcile), containers, images, volumes
internal/common/         shared infra: http (standard headers), logging
internal/modules/doorman/   SQL module (doorman): instance create (postgres/mariadb/mysql),
                        query, alter, rollback (dry-run tx), analytics; engine descriptors
                        and client argv live here; mechanics in repositories/docker
internal/constants/     universal defined values (Version, ConsumerGroupPrefix, status states)
internal/control.go      master's operations core (registry repo + Kafka + memory)
internal/common/         http (standard headers), logging, idgen (dashless uuid), sign (HMAC)
internal/entity/         domain models + Config (env struct, go-validator)
internal/interfaces/     all seams + data shapes (NodeRepository, Docker); implementers
                         assert `var _ interfaces.X = (*Impl)(nil)` next to their structs
internal/features/doorman/   decisions only: network isolation boundary (noxis-<node> bridge per node); container decisions return later
docker/                  docker-compose.yml (Kafka + master + slave) + db.sqlite

REST: controller package holds one annotated handler per method; routes.go
wires them + middleware. Spec: doc/swagger.yaml|json (OpenAPI 3) generated by
`make swagger`, Postman-only. /healthz only (master is always ready; slaves
rely on identity.json).

State: specs (desired) and statuses (reported) live in master memory + Kafka;
sqlite holds only the slaves registry. Slaves heartbeat every 15s; master
marks a node offline after 30s of silence. Master restart loses memory state
until the next heartbeat/assign (ponytail: replay spec topics if it matters).

Isolation: each slave owns a docker bridge network `noxis-<node>` (label
noxis.network=<node>) — created on the first engine assignment, removed on an
empty spec. Instances join it (network alias = engine name) with a persistent
volume (noxis-<node>-<engine>-data) and dev passwords in env (overridable via
spec env). Restart recovery: master memory refetch via REST (identity.master).

Acceptance: test/uat (godog/Gherkin) covers the same surface as a runnable
contract — node lifecycle, query/alter/rollback/analytics, statement guards,
engine updates (tagged @slow). `make uat`.

Capabilities (verified e2e): create instance (several per node), query
(read-only), alter (DML + DDL), rollback dry-run, analyze; statement-kind
guards are a reads/writes split (query rejects DML + DDL, alter rejects
reads, 400); engine update — same-major
recreates the container and keeps the volume (data survives), major bump gets
a fresh cluster backed by a major-split volume (old data preserved; migration
is the operator's job).

Ceilings/next: instance teardown when engines leave the spec (orphans linger);
true rollback from a DDL changelog (UCM); cluster/HA engines; standby/replica
topologies.
```

CLI is one-shot: `run master`, `run slave <id>` (reads identity, zero env),
`register slave <name>` (identity + master registry). Everything else is REST.

Engines nest under doorman, not beside it: elasticsearch is not a feature,
it's a Doorman-managed engine. Every function takes ctx first; logs
re-emit trace/span ids from the context so log-trace-metric share identity.

Storage decision: sqlite holds only the assignment record (what should run),
the status echo (what slaves report running), and the changelog (audit/oplog).
Actual runtime lives on the machine (docker ps), read fresh on every
reconcile — no duplicated state, no double-apply by design.

## Phases

- [x] 0 Scaffold — `noxis master` / `slave` / `assign` / `status` / `sync` CLI
- [x] 1 Core transport — Watch stream push + replay on reconnect, GetDesiredState fallback, ReportStatus. Verified: master death → slaves survive, engines keep running → restart → reconnected + converged
- [x] 2 Doorman engines — postgres/mysql/mariadb/mongo/redis/elastic descriptors + docker driver (CLI shell-out, node-labeled isolation)
- [x] 3 Desired-state converge — assign → push → slave start/upgrade/remove; node-scoped listing stops cross-node theft on shared docker hosts; port conflicts surface as clear per-node errors; custom host ports `TYPE@VER:HOSTPORT`; config drift (version/port/env) recreates via the stamped `noxis.desired` label
- [x] 3.5 Read queries (transport preserved; slave answers no-runtime error until engines return)
- [x] 3.6 Docker repository: networks, container lifecycle, images, volumes behind interfaces.Docker
- [x] 3.7 golangci-lint configured (`make lint`), zero issues; named constants for all domain strings
      (resource prefixes, label keys, consumer-group prefix, version) (transport preserved; slave answers no-runtime error until engines return) — `query NODE ENGINE "SQL"` routes over the bidirectional Watch stream (no slave listeners, no addr registration); slave executes via the engine's own SQL client with its creation credentials; SQL engines only
- [ ] 4 UCM — versioned config entities, `get/set/history` verbs, oplog replication to slaves
- [ ] 5 Ops — backup-before-upgrade, `apply --node X` manual gate, `--promote`, systemd units for agents
- [ ] 6 Polish (only if needed) | mTLS, web UI

Known ceilings (ponytail): proto supports `ports`/`env` overrides but CLI `assign` doesn't set them yet; containers recreate on image change only — env/port edits need manual `docker rm -f` + `sync`.

## Non-goals

- Multi-DC, multi-master, auto-failover, audit webhooks, Kubernetes. Never / when a real trigger appears.

## Risks

- **Data loss on upgrade** — mitigated by phase 5 backup gate, never skipped.
- **Scope creep** — this stays a handful of packages; each new service = thin layer on core, not a new framework.
- **Two-node raft temptation** — reject; 2-node consensus is ceremony, manual promote wins.
## Authentication & access control (OIDC + per-connection RBAC)

Identity and policy are split: the OIDC provider (Authentik) owns *who* a
caller is and *which groups* it holds; noxis owns only *which group may touch
which instance, at what level*. No user store, no roles — one policy table.

- **Auth:** bearer-only. `NOXIS_OIDC_ISSUER` unset = open (single operator, with
  a startup warning); set = every `/v1/*` request needs a valid token, verified
  against the issuer's JWKS (`iss`, `aud`, `exp`, signature). The console runs
  Authorization Code + PKCE (public client, no secret) and refreshes its own
  token; the server never handles cookies or refresh tokens. Config:
  `NOXIS_OIDC_ISSUER`, `NOXIS_OIDC_CLIENT_ID`, `NOXIS_OIDC_AUDIENCE` (default
  client id), `NOXIS_OIDC_GROUPS_CLAIM` (default `groups`),
  `NOXIS_OIDC_ADMIN_GROUP` (implicit global admin).
- **Policy:** `connection_grants(connection, group_name, level)` with
  `read < write < admin`, default deny, effective level = strongest matching
  grant. Managed by global admins at
  `/v1/{engine}/connections/{name}/grants`. Open mode and global admins bypass
  the per-connection check.
- **Enforcement:** `controller.raw(ctx, mod, name, level)` is the single gate;
  list endpoints hide what the caller cannot read. Level map: read = browse,
  query, stats-free reads; write = alter, rollback, analyze, submit; admin =
  approve/apply/reject, flush, key removal. `GET /v1/me` exposes the caller and
  its per-connection levels; `GET /auth/config` is the public console bootstrap.
